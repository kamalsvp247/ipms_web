The Algorithm Monitor's "processing" phase (download-complete → `processing_completed_at`) was ~3.1s while the bundle download itself was <1s. Root cause: `analyze_captcha_algo.py` spawns **two cold Node processes that each parse+execute the entire ~2.1 MB IVAC React bundle** — `_extract_constants_via_node` (~1.28s, captures secret vars + call-sites) and `_compute_live_outputs` (~1.2s, runs the live encrypt modules for ground truth). Not algorithmic complexity — two full V8 re-executions of a large front-end bundle. (Node cold-start itself is ~10ms; regex scans over 2 MB are ~2ms.)

**Fix (Jul 1 2026):** content-addressed memoization in `analyze_captcha_algo.py` — both Node results are cached in `storage/app/captcha/analysis_cache/<key>.json` keyed by the bundle's content hash (`_extract_constants_via_node` wrapped by a `_uncached` inner fn; the live-runtime `data` cached inside `_compute_live_outputs`, so the encrypt_meta write side-effect still runs on hit). Extraction is a pure function of bundle bytes, so a byte-identical bundle (normal state between redeploys) skips both evals. Result: cold/redeploy still ~3s (must execute new code once), **repeat/unchanged ~205ms** (15× faster). Cold vs warm JSON output is byte-identical.

**KEY GOTCHA:** cache key must hash the bundle with `dump_bundle`'s prepended `// source: <url>` header line(s) STRIPPED (`_bundle_identity()`). `dump_bundle` prepends that header on every write; on the local `--bundle` path (which re-reads the same file) the header ACCUMULATES, so naive `sha256(js_code)` changes every run → permanent cache miss. Production masks this because the edge fetcher overwrites `ivac-bundle.js` with fresh raw bytes before each run — but always key on the header-stripped identity so it's robust on both paths.

Cache is never invalidated (different bytes ⇒ different key); pruned to newest 40. Root-owned cache files from a tinker/manual run are harmless (reads work; www-data can rename-over them since the dir is www-data:775). Related: [[project_captcha_live_js_engine]], [[kb_captcha_algorithm_verification]].

**Third phase = sidecar reload (Jul 1 2026).** Total (download→healthy) has a THIRD phase after processing: `activate()` → `LiveBundleClient::reload()` → sidecar `/reload` synchronously re-evals the 2 MB bundle (~1.1s). Profiled breakdown of that reload: read 4ms, hash 2ms, patch(regex) 13ms, **V8 compile 49ms, execute(run) ~1100ms** — it's pure single-threaded bundle EXECUTION (esbuild scope-hoisted, whole React app boots eagerly just to define the 10 `encryptText` modules, which sit at the very END of the file so you can't truncate). Proven dead-ends for the new-bundle case: V8 code cache saves only the 49ms compile (post-run cache doesn't cut exec); bigger young-gen doesn't help (GC ~45ms, not the bottleneck); `--no-turbofan`/`--no-opt` nearly DOUBLE it (default JIT already optimal); no hot spot to neuter; no GPU/parallel path (single-threaded JS). So a genuine-rotation reload is ~1.1s irreducible in-isolate.
**Fix shipped:** unchanged-bundle fast path in `captcha_encrypt_server.cjs` `load()` — hash the file (~2ms) and if it equals the loaded `state.bundleHash`, call `refreshMetaOnly()` (re-read the tiny meta, keep the compiled encrypt closures) instead of `runtime.load()`. Re-running analysis / re-activating the current bundle now reloads in ~3.5ms (was ~1.1s, ~300×). This ALSO removes the ~1.1s event-loop encryption stall that every unchanged reload used to cause. Test: `tests/Feature/Captcha/CaptchaSidecarReloadTest.php` launches the real sidecar on synthetic bundles, asserts unchanged→"skipped re-eval" + changed→full reload (new hash/modules).

**NEW-BUNDLE optimization (Jul 4 2026) — both remaining levers shipped.** For a genuine redeploy the pipeline used to execute the 2 MB bundle THREE times (analyzer boot#1 secret probe ~1.7s + boot#2 ground-truth ~1.25s + sidecar reload ~1.1s). Two changes cut it to ONE execution on the critical path:
- **Part A — single-boot merge.** New `app/Scripts/captcha_probe.cjs` evaluates the bundle ONCE and returns BOTH the resolved secrets/charset AND every call site's live ground-truth encrypt output. Python `_run_bundle_once(js_code, bundle_path)` (memoized, cache key `probe_v2_<identity>`) drives it; `_extract_constants_via_node` (now a thin adapter) and `_compute_live_outputs` both read that one cached result → **1 node boot, not 2**. The probe reuses the runtime's `patchBundle` (DOM stub + **neutered React render** — this is why one boot is ~1.25s not ~1.7s) + `wellformedReason`; capture-patching stays in Python (`_build_capture_patch`). Cache bumped v1→v2 (old `consts_`/`live_` entries ignored). Proven **byte-identical old-vs-new** on the archived corpus AND the full `analyze()` output incl. the ground-truth tokens + encrypt_meta. Full cold `analyze()`: ~3s → **~1.8s, 1 boot** (verified by counting `subprocess.run` node spawns).
- **Part B — double-buffer promote (the previously-blocked lever).** `captcha_encrypt_server.cjs` gains a module-level `staged` slot + `POST /stage` (acks 202, evals the on-disk bundle into `staged` on `setImmediate` WITHOUT touching live) + `POST /promote {bundle_hash}` (instant swap when `staged.bundleHash===hash`, else falls back to a full `load()` — never worse than the old reload). The "shared `__IVAC_ENC` / identical module names" blocker was a non-issue: each `runtime.load()` already snapshots its OWN `registry` local, so staged and live closures are independent (no per-context vm needed). `CaptchaAlgorithmService::tryFetchBundleViaEdgeIps` fires `sidecar->stage()` right after the edge download so the ~1.1s stage overlaps the Python boot; `CaptchaBundleVersionService::activate()` calls `sidecar->promote($hash)` instead of `reload()` → instant on the fast path. **Critical enabler:** `dump_bundle()` is now a NO-OP on the edge path (source==BUNDLE_DUMP_PATH) — it used to prepend a `// source:` header that changed the bytes the sidecar staged, breaking the promote hash match (and it also killed the header-accumulation footgun). Tests: extended `CaptchaSidecarReloadTest` (stage-doesnt-touch-live + instant promote + mismatch→fallback); `CaptchaBundleVersionServiceTest` activate mocks updated `reload`→`promote`. `LiveBundleClient` gains `stage()`/`promote()`. Deployed: sidecar restarted (systemd `ipms-captcha-encrypt`), live promote verified on the real 2.2 MB bundle. Net: download→healthy ≈ download + ~1.8s (was + ~4.1s). `reconcileActiveFiles()` unchanged (still `reload()` — unclean path clears `staged`). Pre-existing unrelated red: `CaptchaAlgorithmGroundTruthTest` "enables disabled captcha providers".

**`_detect_charset_var` optimization (Jul 6 2026) — the last cheap Python lever.** After the single-boot merge, cold "processing" was still ~2.05s; a phase profile showed the ~1.21s **node bundle eval is the irreducible floor** (CPU-profiled: dead-flat, hundreds of ~6-10ms fns, NO hot spot — confirms the memory's "irreducible in-isolate" claim on the current bundle; warm sidecar reuse would save only ~10ms node-spawn since the eval can't hide behind the 956ms download — capture-patch needs the bytes first). The one safe win was `_build_capture_patch` (413ms), of which **`_detect_charset_var` was 255ms**: it ran a full-2 MB backtracking `re.search` (`(^|[\s,;{(])(const|let|var)?\s*VAR=([^;\n]{40,800})`) once PER candidate `[X+"h"]` var (~10). Replaced with a cheap literal `VAR=` scan (`re.finditer(re.escape(var)+r'\s*=(?!=)')`) + LOCAL validation (16-char left-boundary slice for the delim/decl prefix; RHS sliced to 800 then cut at first `;`/`\n`, require len>=40, count `+`), memoized per var. **Byte-identical output** verified on the live bundle + all 28 archived bundles (`storage/app/captcha/bundles/`). Result: `_detect_charset_var` 255ms→~10ms, `_build_capture_patch` 413→163ms, **cold `--attribute` end-to-end 2.05s→1.72s (~16%)**; extraction correct (login/reserve skip/enc_len/version, wellformed, distinct all pass). `CaptchaAlgorithmCorpusTest` green (3 pass / 1 pre-existing skip = deleted `21674522` fixture / 54 assertions). **Rejected as not worth it:** in-memory memo of the 2nd `_run_bundle_once` call (disk-cache hit is 0.02ms); bundle-slicing to skip the React eval (fragile vs version rotations — against the "run the site's own code" design). Only `analyze_captcha_algo.py` changed (Python read fresh each run — no `npm run build`, no FPM reload needed).
